# Метод Монте-Карло
> Знаходьте ймовірності та інтеграли, імітуючи випадковий експеримент.

Ідея: замість формули — мільйон випадкових дослідів і підрахунок. Точність зростає як `1/√n`.

### Оцінка числа π

Випадкові точки в квадраті `[0, 1]²`; частка тих, що потрапили в чверть кола `x² + y² ≤ 1`, дорівнює π/4.

```r
set.seed(1)
n <- 100000
x <- runif(n); y <- runif(n)
inside <- x^2 + y^2 <= 1
4 * mean(inside)
```

### Оцінка інтеграла

`∫₀¹ f(x) dx ≈ середнє f(U)`, де `U` рівномірні на `[0, 1]`:

```r
f <- function(x) exp(-x^2)
set.seed(2)
mean(f(runif(1e5)))
integrate(f, 0, 1)$value      # чисельний інтеграл для порівняння
```

### Парадокс днів народження

Імовірність, що серед 23 людей двоє мають однаковий день народження:

```r
set.seed(3)
same <- replicate(10000, any(duplicated(sample(365, 23, replace = TRUE))))
mean(same)
```

### Задача Монті Голла

За одними з трьох дверей — автомобіль. Ви обираєте двері, ведучий відчиняє порожні, ви вирішуєте змінити вибір. Стратегія «змінити» виграє, якщо первинний вибір був **неправильним**:

```r
set.seed(4)
n <- 10000
car <- sample(1:3, n, replace = TRUE)
pick <- sample(1:3, n, replace = TRUE)
mean(pick != car)       # частка виграшів при зміні — ≈ 2/3
mean(pick == car)       # якщо не змінювати — ≈ 1/3
```

### Ризик у моделі прибутку

Дохід ~ N(100, 25), витрати 90. Імовірність збитку (дохід < витрат):

```r
set.seed(5)
revenue <- rnorm(1e5, 100, 25)
mean(revenue < 90)
pnorm(90, 100, 25)       # точна відповідь
```

## Завдання: Оцінка π
Згенеруйте `n = 100000` випадкових точок у квадраті `[0, 1]²` та оцініть π як `4 × частка точок усередині чверті кола` — змінна `pi_hat`.
```r starter
# set.seed(1)
# n <- 100000
# pi_hat <- ...

```
```r solution
set.seed(1)
n <- 100000
x <- runif(n)
y <- runif(n)
pi_hat <- 4 * mean(x^2 + y^2 <= 1)
```
@hint Дві незалежні вибірки `runif(n)` задають координати точок.
@check uses=runif
@test exists("pi_hat") && abs(pi_hat - pi) < 0.03 => pi_hat має бути близьким до 3.14159.

## Завдання: Інтеграл методом Монте-Карло
Оцініть `∫₀¹ e^(−x²) dx`, усереднивши значення функції в 100 000 випадкових точках `U(0, 1)`. Результат — змінна `integral`.
```r starter
# set.seed(2)
# integral <- ...

```
```r solution
set.seed(2)
integral <- mean(exp(-runif(1e5)^2))
```
@hint Інтеграл ≈ середнє значення `exp(-u^2)`.
@check uses=runif
@test exists("integral") && abs(integral - 0.7468241) < 0.01 => Значення має бути близьким до 0.7468.

## Завдання: Дні народження
Оцініть імовірність, що серед 23 людей є принаймні двоє з однаковою датою народження, виконавши 10 000 симуляцій. Результат — `p_same`.
```r starter
# set.seed(3)
# p_same <- ...

```
```r solution
set.seed(3)
same <- replicate(10000, any(duplicated(sample(365, 23, replace = TRUE))))
p_same <- mean(same)
```
@hint Збіг у вибірці знаходить `any(duplicated(...))`.
@check uses=replicate
@test exists("p_same") && abs(p_same - 0.507) < 0.03 => Очікується приблизно 0.507.

## Завдання: Монті Голл
Змоделюйте 10 000 ігор. Збережіть у `win_switch` частку виграшів стратегії «змінити двері».
```r starter
# set.seed(4)
# car <- ...
# pick <- ...
# win_switch <- ...

```
```r solution
set.seed(4)
n <- 10000
car <- sample(1:3, n, replace = TRUE)
pick <- sample(1:3, n, replace = TRUE)
win_switch <- mean(pick != car)
```
@hint Зміна виграє тоді й тільки тоді, коли початковий вибір був хибним.
@check
@test exists("win_switch") && abs(win_switch - 2/3) < 0.03 => Імовірність виграшу при зміні дверей — близько 2/3.

## Завдання: Ризик збитку
Дохід господарства ~ N(100, 25), витрати — 90. Методом Монте-Карло (100 000 значень, `set.seed(5)`) оцініть імовірність збитку `p_loss`.
```r starter
# set.seed(5)
# revenue <- ...
# p_loss <- ...

```
```r solution
set.seed(5)
revenue <- rnorm(1e5, 100, 25)
p_loss <- mean(revenue < 90)
```
@hint Збиток — подія `revenue < 90`.
@check uses=rnorm
@test exists("p_loss") && abs(p_loss - pnorm(90, 100, 25)) < 0.01 => p_loss має бути близьким до pnorm(90, 100, 25) ≈ 0.345.

## Тест: Точність Монте-Карло
У скільки разів потрібно збільшити кількість дослідів, щоб похибка зменшилась у 10 разів?
- [ ] у 10
- [x] у 100
- [ ] у 1000
- [ ] точність від кількості не залежить
@explain Похибка пропорційна `1/√n`. Щоб зменшити її в 10 разів, `n` треба збільшити в 10² = 100 разів.
